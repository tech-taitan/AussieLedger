## Phase Boundary

Phase 13 ships AussieLedger as an installable Progressive Web App via `vite-plugin-pwa@^1.3.0` using the `generateSW` Workbox strategy with `registerType: 'prompt'`. Adds a `manifest.json`, icon assets (192/512 standard + 192/512 maskable + 180 apple-touch), a service worker that precaches the SPA shell, and an in-app update banner that surfaces when a newer SW is available. Service worker activates ONLY in production builds — `npm run dev` behaviour is entirely unchanged. Together with Phase 11's iOS ITP banner (which auto-hides once `display-mode: standalone` is detected), this completes the iOS-Safari mitigation story: users install to Home Screen → ITP 7-day wipe timer resets on each launch → backup-nag remains the safety net.

**In scope (1 requirement: PWA-01):**
- **`vite-plugin-pwa@^1.3.0`** added as a devDependency; configured in `vite.config.ts` with:
  - `registerType: 'prompt'` (NOT `'autoUpdate'`)
  - `strategies: 'generateSW'` (NOT `'injectManifest'`)
  - `workbox: { skipWaiting: true, clientsClaim: true, cleanupOutdatedCaches: true }` — **all three required** per PITFALLS §3 HARD-BLOCK
  - `devOptions: { enabled: false }` — service worker never registers in `npm run dev`
  - `workbox: { globPatterns: ['**/*.{js,css,html,svg,png,woff2}'] }` — Workbox default for SPA shell precache; NO runtime caching for `/api/*` (NetworkOnly default)
- **`manifest.json` generated by the plugin** (no hand-authored file) with:
  - `name: "AussieLedger"`
  - `short_name: "AussieLedger"` (12 chars; fits iOS home-screen truncation at 11–12)
  - `description: "Free Australian bookkeeping → tax return tool. Your data stays in your browser."`
  - `theme_color: "#141414"` (the `--ink` brand color; tints iOS/Android title bar)
  - `background_color: "#E4E3E0"` (the `--bg` paper-warm; matches splash screen to actual app)
  - `display: 'standalone'`
  - `start_url: '/'`
  - `categories: ['finance', 'productivity']`
  - `icons` array: 192/512 standard + 192/512 maskable (Android adaptive-icon safe-zone padded)
- **Icon assets** rendered from the existing `lucide-react` `Calculator` icon (matches sidebar header). Render approach: build-time Node script `scripts/build-pwa-icons.mjs` that uses an off-the-shelf library (e.g. `sharp` or `pngjs` + the Calculator SVG path data) to emit PNGs at 192, 512, and 192-maskable (with 20% safe-zone padding), 512-maskable. Visual: `#3b82f6` blue Calculator on `#ffffff` white background (matches sidebar header visual). Output: `public/icon-192.png`, `public/icon-512.png`, `public/icon-192-maskable.png`, `public/icon-512-maskable.png`, `public/apple-touch-icon.png` (180×180).
- **`<link rel="apple-touch-icon" href="/apple-touch-icon.png">`** added to `index.html` head — iOS Safari ignores manifest icons for Add-to-Home-Screen and uses this link instead.

Later snooze stored in `sessionStorage` key `aussieledger:pwa-update-snoozed = 'true'` (re-fires next session if user still hasn't updated). Update action sends `SKIP_WAITING` postMessage to the new SW then `window.location.reload()` on the SW's `controllerchange` event (~100ms).
- **`useUpdateBanner()` hook** (or inline-in-App.tsx state management) wires `registerSW({ onNeedRefresh, onOfflineReady })` from `virtual:pwa-register`. `onNeedRefresh` flips a state flag the banner reads. `onOfflineReady` fires once on first SW install but is intentionally not surfaced as a banner (silent success).

## Implementation Decisions

### Icon assets (4 sub-decisions)

- **Render the lucide-react Calculator icon to PNGs at build time via a Node script** (`scripts/build-pwa-icons.mjs`). Reads the Calculator SVG path data from `lucide-react`'s package (or hardcodes the path string), rasterises at 192/512/180 with `sharp` (or pure-JS canvas fallback). Outputs to `public/`. Committed PNGs ensure deterministic builds — script runs once, output checked into git, regenerated only when icon design changes. Matches the existing sidebar header (Calculator icon in `#3b82f6` blue) so users see continuity between in-app branding and home-screen icon.
- **Both standard AND maskable variants** (192 + 512 each + 180 apple-touch). Total 5 PNG files. Maskable variants have 20% safe-zone padding (Calculator icon occupies central 60% of the canvas; outer 20% on each side is solid white) so Android adaptive icons crop cleanly into circle/squircle/teardrop shapes without clipping the icon strokes.
- **iOS apple-touch-icon at 180×180** declared via `<link rel="apple-touch-icon" href="/apple-touch-icon.png">` in `index.html` head. iOS Safari ignores manifest icons for Add-to-Home-Screen — uses this link tag instead. Without it, iOS shows a generic blurry page-screenshot as the home-screen icon (visibly unpolished, especially since Phase 11's IosItpBanner actively directs iOS users to install).
- **Visual: `#3b82f6` blue Calculator icon on `#ffffff` white background.** Matches the existing sidebar header verbatim (`<Calculator className="text-blue-600" />` in `Sidebar.tsx:161`). White background ensures the icon is legible at small home-screen sizes; blue is recognisable in a grid of finance/productivity apps. NOT inverted (white-on-ink) and NOT brand-warm (ink-on-paper) — white-bg variant chosen for in-grid contrast.

### Manifest metadata (4 sub-decisions)

- **`name: "AussieLedger"`** — single-word brand. Matches `<title>`, sidebar heading, package.json, GitHub repo, README. Minimal; clean; ~12 chars fits every install dialog.
- **`short_name: "AussieLedger"`** — same as full name (12 chars; fits iOS home-screen truncation at 11–12 chars; Android allows ~25). Avoids the "Ledger" alternative which is less distinctive in a grid full of finance apps.
- **`description: "Free Australian bookkeeping → tax return tool. Your data stays in your browser."`** — 95 chars. States the core value (free + Australian + bookkeeping + tax) AND the privacy guarantee (data stays in browser) in one sentence. Matches the README opening pitch. Visible in Chrome's PWA install dialog and Android's "App info" surface.
- **`theme_color: "#141414"`** (the `--ink` CSS variable) **+ `background_color: "#E4E3E0"`** (the `--bg` paper-warm). Theme color tints the iOS/Android title bar and PWA window chrome — black ink matches the calm-modernist aesthetic. Background color is the splash screen colour before JS loads — paper-warm matches the actual app body background, so the transition from splash → app is seamless (no jarring white flash). NOT the blue-theme variant (would diverge from the in-app palette) and NOT the white-background variant (would create a splash-flash on first launch).

### Update banner UX (4 sub-decisions)

- **Top-of-app banner placement** — sibling to `AdapterFallbackBanner` in the layout shell. Visually consistent with the existing storage-mode banner (same visual family). Banner persists across page navigations within the SPA. Doesn't steal focus from in-progress forms. The `<Toast>` primitive is the wrong fit here (transient, easy to miss).
- **Copy: `"A new version of AussieLedger is available."`** + **Update** button (primary, blue/ink-coloured) + **Later** button (secondary, neutral). Names the app explicitly so users with multiple PWAs installed know which one updated. Phrasing is informational, not urgent — matches the calm aesthetic.
- **Persistent within session; Later snoozes for current session only.** SessionStorage key `aussieledger:pwa-update-snoozed = 'true'` set on Later click; banner hides. On next browser session (new tab/window/reload), if SW still has a pending update, banner re-fires. Forces eventual update without nagging mid-session. Note: this differs from the IDB-04 ITP banner snooze (which uses sessionStorage for its own key); two different sessionStorage keys, two different banners, both per-session.
- **Update action: postMessage `{ type: 'SKIP_WAITING' }` to the waiting SW, await `controllerchange` event, then `window.location.reload()`.** Standard Workbox `registerSW` pattern (the `vite-plugin-pwa` README documents this verbatim). User sees one reload; new bundle takes over cleanly with no stale-asset flash. Helper function `triggerSwUpdate()` exported from the registration module for testability.

### Cache strategy + install-prompt scope (4 sub-decisions)

- **Precache the Workbox default: SPA shell (HTML + JS + CSS + emitted assets in `dist/`).** `globPatterns: ['**/*.{js,css,html,svg,png,woff2}']` — Vite emits hashed asset names per build so precache invalidation is automatic. Google Fonts (Inter + JetBrains Mono) are external (https://fonts.googleapis.com / fonts.gstatic.com) — NOT in our origin, NOT precached; cached at runtime by the browser's HTTP cache (works offline after first visit). Total precache: ~2 MB; well under any size budget. SPA loads fully offline after first visit.
- **No runtime caching for `/api/*`** — `urlPattern: /\/api\//, handler: 'NetworkOnly'` in Workbox `runtimeCaching` config (explicit, not just relying on default). Server adapter mode (self-host) serves live small-firm data; cached responses would risk showing stale TB / ledger entries. LocalAdapter mode (hosted) doesn't make `/api/*` calls anyway — the probe 404s harmlessly; AdapterFallbackBanner shows the "Running on Local Browser Storage" disclosure.
- **Offline UX: warn-and-degrade** — the precached SPA loads offline; LocalAdapter writes to IndexedDB which works offline; ServerAdapter mode fails gracefully through the existing `AdapterFallbackBanner` if the server is unreachable. No new offline-specific UI; no `navigator.onLine` polling; no read-only mode toggle. Aligns with the v1.2 "data lives in your browser" thesis — the app fundamentally doesn't need the network for local-mode users.
- **No `beforeinstallprompt` button on desktop.** Chrome/Edge/Brave show their own install icon in the URL bar once manifest + SW are valid (the browser-native affordance). Users who want PWA install will discover it. Phase 11's `IosItpBanner` already covers the iOS Add-to-Home-Screen install flow with explicit instructions. Avoiding an in-app "Install" CTA matches the calm-modernist anti-feature stance (no aggressive PWA install nag — explicit non-goal in REQUIREMENTS.md).

### Claude's Discretion

- **Exact `vite-plugin-pwa` minor version pin** — planner picks the latest `^1.3.x` stable at planning time
- **Icon-rendering library choice** (`sharp` vs `pngjs` + canvas vs headless-chrome via `playwright`) — planner picks the cleanest cross-platform option; `sharp` is most common but has native-build complexity (similar to `better-sqlite3` on Windows); pure-JS alternative may be cleaner. The Calculator icon is simple enough that a few lines of `<canvas>` API in a Node script could render it without any image library
- **Whether to commit the rendered PNGs or generate them on each build** — RECOMMEND committing (deterministic builds; avoids icon-render-failing-CI scenarios). Re-render only when icon design or colours change
- **Exact `globPatterns` extension list** — `js, css, html, svg, png, woff2` is the recommended starting set; planner adjusts if Vite emits other extensions worth precaching
- **`UpdateBanner` exact visual** (warn-tone vs neutral-tone vs blue/positive-tone) — planner picks; neutral-stone matching the new AdapterFallbackBanner palette is the natural family
- **Whether `useUpdateBanner` is a dedicated hook or inline state in `App.tsx`** — planner picks; hook is cleaner if tests need to isolate the registration logic
- **`virtual:pwa-register` import shape** — planner verifies against `vite-plugin-pwa@^1.3.x` README; the public API is stable but the exact import path can drift across major versions
- **Lighthouse smoke approach** — manual via Chrome DevTools, OR `npx lighthouse` CLI command in the verification task. Planner picks; both are acceptable for v1.2 (no CI gate)
- **iOS apple-touch-icon variants** — single 180×180 is the standard; planner may add 152 / 167 if there's a reason (target users on older iPads), but 180 covers iPhone + most current iPads
- **Whether to also add `theme-color` `<meta>` tag inline in `index.html`** — manifest sets it but older browsers (pre-PWA) read the meta tag. Belt-and-suspenders.

</decisions>

<specifics>
## Specific Ideas

- **Calculator icon path data** — extract from `lucide-react`'s exported icon path data (no need to clone the SVG file); render via Node's `<canvas>` API (available in Node 22 native) or `node-canvas` (devDependency)
- **Maskable safe-zone padding** — Calculator icon occupies central 60% × 60% of the 192/512 canvas; outer 20% (top/bottom/left/right) is solid white. Per W3C maskable spec, this guarantees clean cropping on Android adaptive-icon shapes (circle, squircle, teardrop, rounded-square)
- **`registerSW` import** — `import { registerSW } from 'virtual:pwa-register'` — virtual module emitted by `vite-plugin-pwa`; planner verifies the import path against the installed `^1.3.x` version
- **`onNeedRefresh` vs `onOfflineReady` semantics** — `onNeedRefresh` fires when a new SW is detected as `waiting` (means a new build has been published; user is on the OLD SW). `onOfflineReady` fires the first time a new SW activates (means precache is complete; offline now possible). Phase 13 surfaces `onNeedRefresh` as the update banner; `onOfflineReady` is silent (no positive-state banner — match the v1.2 anti-nag stance)
- **SW skip-waiting + reload pattern** — `const updateSW = registerSW({ onNeedRefresh })` returns a function; calling `updateSW(true)` triggers `SKIP_WAITING` postMessage + reload. Wrap in `triggerSwUpdate()` helper for testability
- **`virtual:pwa-register` types** — `vite-plugin-pwa` ships TypeScript definitions; add `/// <reference types="vite-plugin-pwa/client" />` at the top of `useUpdateBanner.ts` if `import.meta.env`-like type inference is needed
- **Manifest test** — `src/__tests__/pwa-manifest.test.ts` reads `dist/manifest.webmanifest` after `npm run build` (test depends on a build artifact; planner picks: run after build in CI, or skip in `npm test` and only run in a verification step)
- **`UpdateBanner` sessionStorage key** — `aussieledger:pwa-update-snoozed` (different from Phase 11's `aussieledger:ios-itp-banner-dismissed` to keep concerns separate)
