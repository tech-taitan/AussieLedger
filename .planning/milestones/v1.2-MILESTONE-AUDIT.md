## Tech Debt (accepted; non-blocking)

### 1. Private repo URL → broken anonymous links (RED→deferred to v1.3)
**Surface:** `README.md:91` + `src/components/PrivacyPage.tsx:55`, `:59`, `:89`. All link to `https://github.com/tech-taitan/AussieLedger`.
**Symptom:** Anonymous browsers (the entire target audience clicking through README to verify open-source claim) hit GitHub 404. User push + CI + Vercel-deploy all work because they're authenticated.
**Cause:** Repo is private. Apache 2.0 open-source promise is undermined when the repo isn't actually public.
**Resolution options:** (a) flip GitHub Settings → Danger Zone → Change to public (one click, ~10s), (b) strip repo URLs from README + PrivacyPage.
**Decision:** User deferred to v1.3 polish at audit time.

### 2. Legacy-migration runs against demo DB construction (AMBER, v1.3)
**Surface:** `src/storage/local.ts:117-122` — `migrateLegacyLocalStorage(this)` runs in LocalAdapter constructor regardless of `dbName`.
**Symptom:** Pre-Phase-11 user with legacy localStorage data who lands on `/demo` BEFORE ever loading `/` has their legacy data migrated INTO the demo DB and legacy keys cleared. Subsequent `/` visit shows empty prod DB.
**Probability at v1.2 release:** Very low. Any legacy user almost certainly hit `/` at least once in v1.0/v1.1.
**Fix (v1.3):** guard with `if (this.dbName === DB_NAME_PROD)` in the constructor, OR skip in `legacy-migration.ts` when route is demo.

### 3. UpdateBanner z-index stacking (AMBER, v1.3)
**Surface:** `src/components/UpdateBanner.tsx` uses `fixed top-0 z-50`; MainLayout banners (AdapterFallbackBanner, DemoModeBanner) are in normal flow.
**Symptom:** If UpdateBanner fires while an in-flow banner is showing, brief visual overlap at the top of the page.
**Probability:** Very low (UpdateBanner fires only on a deploy mid-session).
**Fix (v1.3+):** Revisit stacking strategy if a third floating banner accrues.

### 4. Pre-existing `<button>`-in-`<button>` Sidebar warning (carried from v1.1)
**Surface:** Sidebar NavButton renders anomaly badge `<button>` nested inside nav item `<button>`. React console warning. All Sidebar tests pass.
**Origin:** Phase 6; carried through v1.1 (flagged in v1.1 audit) and now through v1.2.
**Fix (v1.3 polish):** badge → `<span role="button">` with keyboard handling OR restructure NavButton.

### 5. VALIDATION.md convention shift (notable; not a defect)
**Observation:** v1.0 + v1.1 phases shipped both VALIDATION.md (Nyquist frontmatter) AND VERIFICATION.md (plan-checker output). v1.2 phases shipped VERIFICATION.md only.
**Cause:** The /gsd:plan-phase workflow started writing VERIFICATION.md as the single audit artifact during v1.2 — natural workflow evolution; same data, single file per phase.
**Impact:** v1.2 milestone audit relies on VERIFICATION.md for the per-phase audit signal. Frontmatter `nyquist:` field marked `not-applicable` to reflect this.
